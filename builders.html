Builders

Reported in the session that wrote it

Coding agents are agents. They are subject to the same inference violations, drift, and stochastic behavior as any other LLM agent, and teams now often use them to build agentic software.

The seam monitor runs inside the build loop. When a coding agent writes a decision that acts on an interpreted value and reaches something consequential, the note arrives in that same session, before the change is anywhere else.

Inside the build loop

Why a builder reads the note

Any coding agent can write its own code walker in an afternoon. A note worth reading has to carry what a local walk cannot produce: knowledge of the running system not readily or easily accessible to the builder.

Case study

A rule-based calendaring agent

The system
A rule-based agent that calendars deadlines, under development.
What review missed
A conventional implementation review left an authority-bearing dependency unresolved.
What seam analysis found
  • A heuristic inference presented as established information, which then filtered the rules the model was shown.
  • A fuzzy match carrying the same label as an exact one.
What changed
The producer's code did not need to change. The consequential behavior downstream did. Further investigation found more authority-bearing dependencies in rule selection and evaluation context.
What it does not show
A development account, not an independently reproduced study. It shows the gap between a correct producer and an unjustified downstream decision, not a prevented failure.
