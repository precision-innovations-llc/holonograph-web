Chapter 16

Rubric coverage and de-saturation

One rubric over a population with real sub-kinds judges the union weakly, or judges the wrong specifics. This chapter is the loop that fixes that: scope a rubric per facet, see which facets have one, draft the ones that do not, and check that what you drafted can still tell a wrong answer from a right one.

What it is

A grading dimension carries one rubricRef. Point it at a surface whose population is heterogeneous, with members like Daily Summary, Weather Advisory and Weekly Check-in, and that one rubric either grades the union loosely or grades one member's specifics and mis-grades the rest.

rubricDispatch scopes a rubric per facet without enumerating the members in the contract: 

{
  "id": "signal-quality",
  "scoring": "llm-judge",
  "rubricRef": "gs://rubrics/signal-general.md",
  "rubricDispatch": {
    "facet": "signal.name",
    "refsFrom": "gs://rubrics/signal-alert/",
    "refs": { "Morning Routine": "gs://rubrics/pinned/morning.md" }
  }
}
FieldWhat it declares
facetThe cohort-tag key whose per-event value selects the rubric. It has to be a key in the surface's declared cohortTags vocabulary: a bounded identifier, not a human-authored display string with its em-dashes and emoji.
refsFromThe bucket a per-facet rubric resolves from by convention. The rubric for value V is refsFrom + the normalized V + .md. Adding a member's rubric is a bucket write, never a contract change.
refsOptional pins that override the convention for named values. Keys are matched in their normalized form, so pinning Morning Routine addresses the same rubric identity the convention would.

The dimension's own rubricRef is re-cast as the required default. An unknown or unmatched facet is scored against it rather than skipped, because skipping would manufacture the judge-liveness hole the instrument exists to close. It is scored, marked, and counted.

The shared normalization

A facet value and its filename have to address the same rubric, so both the dispatch and the drafter that writes the bucket file call one function. It folds Unicode and strips combining marks, lowercases, collapses every run of non-alphanumerics to a single hyphen, and trims: 

"Morning Routine"                → morning-routine.md
"Weather — Heat Advisory ⚠️"      → weather-heat-advisory.md
"café"                           → cafe.md

A value that is entirely non-alphanumeric, a bare emoji say, normalizes to nothing. That is an unaddressable stem, so the planner reads it as an unmatched value rather than pointing at a .md that cannot exist.

Why it matters

Two properties make the loop auditable rather than hopeful.

Why an event rode the default

Every scored event is stamped with which rubric judged it and, when that was the default, why. Four reasons, and they are different problems:

ReasonWhat happenedWhat to do
no-bespoke-refA declared facet value with no per-facet rubric authored yet.Nothing is wrong. This is the drafter's work queue.
unmatched-valueA facet=value tag was present, but the value is not declared and does not normalize to one.A typo or an undeclared member. Fix the tag or declare the value.
facet-tag-absentThe event carried no facet= tag at all.Un-tagged emit. Fix the producer.
pin-unresolvedAn explicit refs pin was set and failed to load.A bad pin. Louder than a convention miss, because you asked for this one by name.

Without the split, the default population is one undifferentiated bucket and a coverage gap is indistinguishable from a broken emitter.

The default vouches for less

A default-scored event is also reduced-reach. The surface-general rubric vouches for surface-general correctness, not for domain quality, so it is deliberately strict about what it can see and silent about what it cannot. Scores under it are not comparable to scores under a bespoke rubric, and the lens treats the difference as a property of the instrument rather than of the agent.

How to use it

Read the worklist

GET /lens/facet-coverage?surfaceId=signal-alert

One report per dispatching dimension. The counts are the readout: facetsSeen against bespokeCount, scoredOnDefault split by reason, untaggedCount, and defaultOnly for the facets that have never had anything but the default. facets carries the per-facet detail, each entry naming its source and, where that is default, its defaultReason.

Re-derived per read from the apparatus columns. A surface with no dispatching dimension returns empty rather than zero.

Draft one

POST /lens/rubric/propose
{
  "surfaceId": "signal-alert",
  "dimensionId": "signal-quality",
  "facetValue": "Morning Routine"
}

The deterministic scaffold is assembled server-side from the contract: the dimensional-context header and the required verdict shape come from rubricDispatch and judgeClaimContract. The narrator contributes the domain grading criteria and nothing else. It has no channel through which to emit a number, so a fabricated threshold is structurally impossible rather than merely unlikely.

The response carries the refPath the approved body belongs at, the draft, and two honesty flags. narratorStatus is llm when a real narrator produced the criteria, stub when none is configured, and stub-fallback when one was configured and threw: a draft returned under stub-fallback is a deterministic skeleton and must not read as an authored proposal. evidenceAvailable flags whether the count behind the draft was measured or is a placeholder.

Propose-only. The draft goes to the approver gate, and the approved body is what the operator writes to the bucket. The lens never writes the rubric.

Check that it discriminates

A rubric can be authored, resolved, and scoring, and still be blind. If a value sits in the judge's sight and the rubric never asks about it, an output that is wrong along that value scores as if it were right. The score saturates. 

POST /lens/saturation/audit
{
  "surfaceId": "signal-alert",
  "dimensionId": "signal-quality"
}

The audit reads the dimension's declared expectsGrounding axes and, for each, computes the pass-rate of the declared misuse values against the dimension's passThreshold.

Per axisMeans
blindThe misuse passes at or above the blind threshold, 0.5 by default. The judge is letting it through.
discriminatingThe misuse reliably fails.
unverifiedToo few misuse samples, five by default, or no declared passThreshold. Honest-null, not a pass.

The dimension's verdict is saturated, discriminating, unverified, or no-expectation where nothing was declared to check. Each axis also reports its misuse and correct-use counts, both pass-rates and the mean misuse score, because a working judge passes correct use and fails misuse, and seeing only one half of that is not evidence.

The verdict is a pass-rate An earlier version of this check asked whether the score varies with the axis at all. That is the wrong question. A judge scoring the misuse 8.4 against a correct 9 varies significantly and still passes the misuse. Separability is not adequate penalization. The verdict is the pass-rate, which is also robust to a judge catching some of the misuse for an unrelated reason: it still reads blind on the fraction it lets through.

No judge is in the loop. The audit reads the substrate alone, because a saturated judge cannot be its own alarm. There is no approver gate and no model call. provenance defaults to all, so a replay panel built by varying the grounding is in scope, and correlationIdPrefix scopes the read to it.

Fan out a focused reviewer

Given measured saturation, the remedy is not to rewrite the holistic rubric. It is to add a reviewer that looks at one thing: 

POST /lens/rubric/desaturate
{
  "surfaceId": "signal-alert",
  "dimensionId": "signal-quality",
  "facetValue": "Morning Routine",
  "blindDimension": {
    "name": "hrv-provenance",
    "description": "whether the HRV figure came from the overnight window it claims",
    "groundingKey": "hrv_metric_type",
    "misuseValues": ["intraday_spot"]
  },
  "saturationEvidence": {
    "scenarios": [
      { "label": "overnight (correct)", "judgeMean": 8.9 },
      { "label": "intraday spot (wrong)", "judgeMean": 8.4 }
    ],
    "replayRunRef": "replay:hrv-probe:"
  }
}

You supply the measured evidence; the server drafts against it. The deterministic facts, the blind dimension and the saturation matrix and the fan-out structure, are pinned server-side, and the narrator writes the focused criteria only. The same discipline as /propose, and the same approver gate.

What comes back is a focused sub-reviewer plus a registrable fan-out fragment: a separate role: 'judge' surface, its routing, and the judgeSurfaceId link that attaches it to the subject dimension. It appends. The holistic rubric is never replaced, because a focused judge that replaced it would trade one blind spot for another.

Declaring misuseValues on the fan-out is what makes it auditable in turn. Omit them and the new judge is not saturation-auditable until you declare them.

What a misuse value has to be The audit keys on the grounding value, so a declared misuse value only discriminates when it is a value the producer consumed that correlates with the wrong output. A value that labels the grounding situation instead admits both a faithful and a faulty output under the same value: the pass-rate mixes the two, lands near half, and mislabels the judge blind. Such an axis is auditable only when the events are scoped to the faulty arm first.

Reading the output

Three apparatus columns are stamped on every dispatched judgment. They are reserved, so a contract may not declare them.

ColumnCarries
judge.rubric_sourcefacet or default.
judge.rubric_facetThe facet value the event dispatched on.
judge.rubric_default_reasonOne of the four reasons, when the source was default.
Which rubric an event got is instrument variance A default-scored population scores systematically lower for instrument reasons. Attributing that gap to the agent is the same mistake as attributing a regional confound to it. judge.rubric_source is a conditioning-permitted axis for exactly this reason, alongside the rubric hash, and the variance decomposition treats both as instrument variance rather than agent variance.

Two of the attention spine's twenty-six sources file from here. rubric-gap is a declared facet riding the default with no bespoke rubric authored, and it mints an author-rubric proposal. rubric-ref-broken is a reference that no longer resolves, and it mints fix-rubric-ref. See The attention spine.

Endpoints

Method & pathPurpose
GET /lens/facet-coverageThe coverage readout per dispatching dimension, with the per-facet detail and the default split by reason.

Contract surface

rubricDispatch, expectsGrounding, judgeSurfaceId and judgeClaimContract are all declared on the grading dimension; see What a dimension declares. The dispatch decision is a published contract, shared by the lens's own gated judge and by an operator's inline one, so both resolve a facet to the same rubric. Resolving the rubric bytes is the caller's: the plan says what to fetch, the caller fetches, and the apparatus columns are stamped from the outcome.

The drafter prompts and the composition order behind /propose and /desaturate ship inside the binary.
