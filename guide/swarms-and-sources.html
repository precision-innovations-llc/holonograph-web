Chapter 07

Swarms and sources

One lens reads a whole swarm. Several agents emit into the same record, often running the same code, and the instrument has to keep them distinguishable without splitting every measurement by agent, because pooling is right in some places and fabricates a statistic in others.

What it is

The source is which agent’s code emitted. It rides on the event as sourceId and is the partition key everything downstream reads.

Two identities are in play and they are not the same one. The agent id is the subject: whose behavior is under evaluation. The source is the emitter: which agent made this call. In a single-agent deployment they collapse into the same thing, which is why the distinction only shows up once a swarm is running.

Surfaces span agents A surface may span several agents in a swarm. The lens identifies a surface by what is being evaluated, never by the agent boundary the data crosses. Two agents doing the same job share a surface and stay separable by source, rather than becoming two surfaces that cannot be compared.

How the source is set

The source is apparatus-owned. The lens stamps it at ingest from the authenticated operator, overriding any value the client sent. A client cannot attribute its events to another agent by asking.

Where no operator identity is established, the single-operator default, the event is left as it came and a client-supplied value stands as plain attribution. The absence of a source means one source, never a fabricated id.

That default is also what keeps a single-agent deployment unchanged. Nothing is stamped, nothing is partitioned, and every identity key is byte-identical to what it was before the swarm model existed.

Why it matters

Three things break without it, and they break in different directions.

Statistics. Pooling two agents’ score populations manufactures correlation that neither agent shows, and a pooled mean can hide one agent’s drift behind another’s stability. Splitting is not uniformly safer: where the instrument is shared, a judge or a global contract, splitting shrinks the sample and asserts a difference that is not there.

Collisions. Swarm agents run the same code. The same seam id, the same call site, the same finding, in several agents at once. Without a partition in the identity, one agent’s evidence silently overwrites another’s and the merged picture is of whichever wrote last.

Authorization. Evidence about one agent’s code is a thing another agent should not be able to replace.

How to use it

Push a scan per agent

POST /lens/builder-seams
{ "source": "orders-agent", "seams": [ ... ], "candidateMap": { ... } }

The declared source is bound to the authenticated identity. A verified operator handing a source that names a different operator is refused with 403, so a scanner cannot replace another agent’s map. Omit it and the lens uses the verified operator’s own id, or the reserved default source where there is no operator identity at all.

The registry holds replace-current per source rather than globally, so several agents’ scans coexist and a push from one never clears another. In the merged read, node identity is the call site, the seam, its version, the direction and the source together, so two agents’ same-string loci stay distinct.

Hold the agent constant

POST /lens/decomposeVariance
{ "surfaceId": "classify-intent", "dimensionId": "correctness", "sourceId": "orders-agent" }

Scoping a decomposition to one source isolates that agent’s subject events, so a mean shift between agents cannot contaminate the variance when one surface is exercised by many. It is the complement of scoping by fixture, which holds the input constant instead.

The judge pool stays unscoped on purpose. A judge call carries the judge’s own source, not the subject agent’s, and is tied to the subject by its linkage rather than by a shared source. Like a replay window, a source scope isolates a diagnostic panel, so the read is ephemeral and is not recorded as the production trajectory.

Read findings scoped to an agent

A finding’s key carries a tagged src= segment, and only where the finding is actually multi-source, so single-source keys are unchanged. Two agents’ identical seam in shared or templated code produce two findings that triage separately instead of colliding into one.

The same composite identity runs through the analysis layer: two agents’ identical templated seam are tested as separate nodes and never pooled into one association, because each agent’s runtime context differs. See The seam monitor.

Reading the output

Every finding source in the attention spine declares how it partitions, so a new producer cannot pool two agents by omission: per-source where pooling corrupts the statistic, pooled-examine where pooling is correct and a hidden split is worth watching for, pooled where the question is global or keyed on another axis entirely. The source-conflation alarm reads the pooled ones and reports where one number is hiding two populations. It points rather than repartitions, because whether a grouping is right is the operator’s call. The attention spine carries the table.

Merged reads preserve composite identity rather than flattening it, so a call site that several agents share keeps every source’s nodes.

Where this sits

The mediating lens is where a call is captured; this chapter is whose call it was. Run modes is the other envelope on the same event, and the two are independent: a source says which agent, a run mode says under what conditions.

The partition vocabulary, the stamped field and the key format are public contract. Which reads scope by source, and how a merged view is assembled, lives in the lens.
