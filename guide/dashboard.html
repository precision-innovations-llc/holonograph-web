Chapter 26

The dashboard

An operator interface ships in the binary. It is a thin client over the reads in the rest of this Guide: every number on it comes from a documented endpoint, so this chapter is an index from the panel you are looking at to the chapter that explains it, not a second account of the instrument.

What it is

The server mounts it when asked, at /dashboard or a configured base path. With it mounted, a request to / redirects there, so an operator who browses the server’s URL with no path lands on the interface instead of an error about the run mode.

The bundle is served ahead of the authenticated router, so its HTML, JS and CSS load without a bearer token. Every /lens/* fetch the page then makes goes through the same auth as any other client. Optional HTTP Basic credentials gate the bundle path itself, which a production deploy should set; local development usually leaves it unset.

Two credentials, two jobs Basic auth on the dashboard path gates the UI bundle and nothing else. The bearer token in the settings dialog is what reads the lens. Setting the first does not protect the API, and setting the second does not hide the page.

Settings holds three things: the lens endpoint, the bearer token, and whether to poll. They persist in the browser. Three URL parameters change the mode without being saved: ?mock=true renders canned data for a demo, ?embed=1 hides the operator chrome for an iframed lens and defaults the palette to dark, and ?theme=light or dark pins the palette for that load only.

The header carries a version chip. It shows the active contract version when one is registered, and falls back to the binary’s own stamp, labelled as such, when none is.

Why it matters

The interface is organized by the four questions an operator actually arrives with, not by the shape of the API. Each tab owns one, and the deeper instruments open over the tab that owns them, so a ceremony has one home.

Nothing on it writes the lens. The exceptions are the gated ceremonies, and each goes through the one shared approver gate described in Authority governance: a triage annotation, a conformance approval, a retention or authority policy, a multiplex run. The apparatus proposes and the operator disposes, on the interface exactly as on the API.

Act is the landing. It is one severity-ranked queue over every finding source, with the jargon moved into the drawer: a row reads “Judge check,” opens into the driver and the sample calls, and takes a disposition with a required rationale. A confirmed defect mints a proposal into Curate. Trust is the standing-health counterpart: the readouts you check before believing a clean verdict. Explore is the bench the other three route down into, scoped by whatever row sent you there.

The three monitors are deliberately outside the Act queue. A seam backlog is a coverage list to work through, not a firefighting queue, and the evidence rides inline on each item, so opening one costs a single read.

The judge transfer curve

One panel has no endpoint of its own. It asks whether a surface’s judge is a graded transfer function or a step function, and it answers from the score distribution the lens already captured, with no new calls to the judge.

CharacterizationWhat a bad reading looks like
QuantizationA handful of distinct scores over a decent sample. The judge is stepping, not grading.
Dead zonesLarge gaps between consecutive achieved scores. Ranges the judge never lands in.
ConcentrationThe most common score holds most of the mass. Barely discriminating.
SaturationEvents piled at the low or high end of the observed range.

What it cannot see is stated on the panel: the perturbation-response cliffs. Finding those means feeding the judge altered inputs, which is a live call and not an observation, so the lens declines. The distribution behind the characterization is in GET /lens/events, and the adjacent question of whether a rubric still discriminates at all is the saturation audit in Rubric coverage and de-saturation.

Deep links

The hash is a route and carries a query string, so a finding, a facet or a desk can be linked directly. An unrecognized tab name falls back to Act.

LinkOpens
#act?severity=&state=&surface=&source=The queue, filtered.
#explore?surface=&facet=&dimension=The rubric drill for one facet.
#explore?event=One event.
#curate?desk=retention&preset=The retention desk, preset applied.
#lens-health · #seam-soak · #builder-seam · #seam-call-analysisThe named monitor, over the tab beneath it.

Reading the output

Where a read is an honest null, the panel says which null it is rather than rendering a zero. Trust shows horizon on a surface whose delivery the lens cannot observe, instead of a reach rate. Trajectory puts its unmeasured accounting first, so events with no boundary key are never read as clean. Verdict reliability shows its review tier separately, labelled as no deterministic check applied, which is not the same as a pass.

The same discipline governs the version chip: with no contract registered it says binary rather than inventing a contract version.

Where this sits

Every panel above is a rendering, and the chapter column is where the measurement itself is explained. Two ceremonies on the interface are the only writes an operator makes often: the triage disposition in Act, covered in The attention spine, and the policy desks, covered in Authority governance and Compaction & husking.

The interface ships with the binary and tracks it. Where this chapter and a panel disagree, the panel is newer.
