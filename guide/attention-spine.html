Chapter 21

The attention spine

Every observe-only surface produces findings, and there are twenty-six sources of them. The spine gives all of them one operator lifecycle instead of one list per surface, and it is the substrate the authority state reads.

What it is

A cross-source triage layer over findings. It declares three objects and nothing else:

ObjectWhat it holds
FindingRefThe stable identity of a finding, independent of the scan that produced it.
TriageRecordAn append-only annotation about that finding.
ProposalWhat a confirmed finding mints into Curate.

The sources

Twenty-six, spanning judge behavior, evaluation structure, coverage, attribution, the store, and the seam work. They are listed here because the spine is only as good as what files into it.

GroupSources
Judge behaviorverdict-reliability, judge-liveness, judge-malfunction, co-groundedness
Evaluation structureorthogonality-hypothesis, primary-axis-orthogonality, redundancy-candidate, pairwise-drift, contested-cohort, rubric-gap, rubric-ref-broken
Coverage and reachcoverage-gap, reach-gap, emission-gap, dark-mass-blindspot, read-window-underpowered

Seams and authoritybuilder-seam, seam-soak, authority-suspended
Storestore-capacity, retention-integrity

A code seam and a model call file into the same spine. They arrive from different sources and sit on adjacent surfaces, and from the lifecycle's side they are the same object.

Several agents on one surface

When several of a swarm's agents emit onto one surface, pooling them is sometimes right and sometimes fabricates a statistic. Every source declares which, so a new producer cannot pool two agents by omission.

PartitionBehavior
per-sourcePooling corrupts the statistic or destroys attribution, so the source runs once per agent and each finding is stamped with its sourceId. A no-op where one surface has one agent. The analytic reads over scores and variance sit here: pooling two score populations manufactures correlation that neither agent shows.
pooled-examinePooling is correct, because the instrument is shared, the contract is global, or the grouping is the operator's and not the lens's to override. The source-conflation alarm checks these for a hidden per-agent split and surfaces it without imposing a partition.
pooledGlobal, or keyed on a different axis entirely: the consumer's agent id, the rubric, the lens's own store. A per-agent split is not meaningful and the alarm ignores it.

source-conflation is the twenty-sixth source and the one that reads the others: it compares agents inside a pooled read and reports where a single number is hiding two populations. It points, it does not repartition. Whether an operator's grouping is wrong is the operator's call.

Three grains

What a finding's identity means depends on its grain: run for one call, conversation for one conversation, and structural for a declared surface, dimension or axis with no single event behind it.

Why it matters

Two invariants hold the spine apart from the measurement it annotates.

A triage annotation never reaches the substrate

An annotation is about a derived finding. It lives in a separate store, downstream of derivation. It is never an input to the lens hash, and it never mutates the substrate, a prompt, or a threshold. The spine proposes; the existing gated approver path disposes. A triage click changes nothing on the lens.

Identity survives re-derivation

Findings are re-derived on every scan. A triage record therefore keys to a content-derived findingKey rather than a per-scan row index. Keying to a row index would orphan every annotation on the next deploy. clusterId stays an attribute, never the primary grain, because a non-deterministic key has the same effect.

How to use it

  • Read findings from the spine rather than per-surface. One queue, one lifecycle.
  • Annotate a finding to record what triage concluded. Annotations accumulate; nothing is overwritten.
  • Mint a proposal from a confirmed finding. The proposal enters the approver path as a proposal, not as a change.

Read the queue

GET /lens/attention?surfaceId=classify-intent&state=untriaged&severity=alarm&limit=50
Authorization: Bearer <token>
x-holonograph-run-mode: production

Filters: surfaceId, source, state, severity, sort, since, until, limit, cursor. Severity is one of alarm, needs-review or coverage, which is the ranking the default sort uses.

Each item carries findingRef and its derived findingKey, the source, the severity, a count of the events that collapsed into it, firstSeen and lastSeen, the inline evidence, the derived triageState, the latestTriage record, how, and gate.

The queue reads without a triage store Without a triage store wired, the queue still returns: every finding reads as untriaged. Writes are what need the store, and POST /lens/attention/triage answers 501 without one. An unconfigured deployment loses the lifecycle, not the observability.

Open one finding

GET /lens/attention/evidence?findingKey=<key>

The decision-grade detail behind one row, fetched when an operator opens it rather than for every row in the queue. It returns a representative exemplar, the most recent flagged call in the class, with the prompt, the model's answer, the judge's verdict and rationale, and the mechanical claims: the tool the judge said was not invoked, the datum it said was fabricated. Alongside it, sampleCount and a samples list to spot-check, plus reAdjudicable and unavailable. Re-derived per read; nothing is persisted. A class that no longer recurs in the window returns an honest-null exemplar rather than a stale one.

Annotate

POST /lens/attention/triage
Authorization: Bearer <token>
Content-Type: application/json

{
  "findingRef": { "primary": { "grain": "structural", "id": "..." }, "attributes": { ... } },
  "disposition": "confirmed-defect",
  "rationale": "the judge passed three misuse samples in a row",
  "approverId": "brian"
}

rationale and approverId are required: an annotation without a reason or an author is not a compliance record. Two optional fields pin what the operator saw, evidenceSnapshotRef for the denormalized slice and asOf for the substrate instant, so a decision stays reconstructible after the evidence moves on. The server stamps occurredAt itself.

Dispositions and states

A disposition is what the operator wrote. A state is what the queue derives.

ValueKindMeaning
confirmed-defectdispositionAdjudicated real. This is the one that mints a proposal.
false-alarmdispositionAdjudicated not real.
acknowledgeddispositionReal and accepted: a known blind spot the operator chooses to leave. Parked, not dismissed.
untriagedstate onlyNo record yet.
resolvedstate onlyThe proposal was applied through Curate, or the finding stopped recurring. A lifecycle signal sets it, never a triage click.

Twelve authoring targets. Each lands in Curate approver-gated, carrying intent rather than an apply-payload: the operator authors the change.

Fourteen of the twenty-six sources mint nothing by default, source-conflation among them. A source with no default proposal is not a lesser finding: it is one where the remedy is a judgment the lens leaves to the operator.

Reading the output

A finding carries its findingRef, the surface and dimension it came from, the run mode it was derived under, and its triage state. Where a finding has an exemplar, the exemplar payload travels with it under the same husk projection used elsewhere in the store, so a triaged finding on a compacted span still opens.

What sits on top

The spine is the base. Authority is a reading over the same record: a per-surface state derived from what the gates, the dependencies and the soak evidence say, re-derived on every read. A surface whose grant is withdrawn files authority-suspended back onto the spine as another finding, which is how a withdrawal reaches the same queue as everything else.

Reflection sits above that again, switched on for a cell once its authority is established.

Endpoints

Method & pathPurpose
GET /lens/attentionThe cross-source queue: findings merged with triage state, severity-ranked, cursor-paginated.
GET /lens/attention/evidenceThe exemplar and sample list behind one finding.
POST /lens/attention/triageAppend one annotation. 501 without a triage store.
GET /lens/trajectory-findingsThe trajectory source read on its own: the turn-to-conversation axis a per-turn judge structurally cannot see. Groups events by the consumer's boundary column, runs the detectors, and returns the findings alongside the honest-null accounting (events with no boundary key, turns with no output text, which predicates actually ran) so an unmeasured slice never reads as clean.

All three are also served under the /holonograph alias. The reads derive per request and persist nothing; the write touches the triage store only, which is not an input to the lens hash.

The public module declares the wire and store contract only. Which surface maps to which FindingRef, and the store implementation, live in the lens package.
