Seams

Where inference becomes a decision

An interpreted value driving a decision that governs a consequential transition is a seam. It is permanent. You can close it and you can monitor it. You cannot validate it away.

What is a seam?

An edge from interpretation to decision

A closed seam

An inference has authority the moment downstream code acts on it as fact. In most systems nobody granted that authority, and nothing records that it happened. Holonograph maps these as seams.

The map has two kinds of node. An interpretive is a value whose meaning is not fixed by its representation: a model output, a classifier, an approximate match, a pattern over free text, an external feed, a recorded human judgment. A decision point is where code acts on that value: a branch, a threshold, a pattern, a lookup key. A seam is the edge between them, written I → DP.

Value interpretation is seam-specific. An interpretive’s consequence changes per seam and is therefore re-derived per seam and node chain, stopping only with the final decision point sink. An exact match over a closed domain is mechanical and carries no seam.

Abstention

Every decision meets input it does not recognize. Abstention is the defined path for that input: the code throws or returns a distinguished no-value, and the gap stays visible. A decision point with that path is attended. A seam is closed when every decision point on its chain is attended and the chain ends in sinks that do not decide.

A seam is open when the remainder falls through to an ordinary value, or when there is no remainder at all. In the walk below, a ticket neither pattern recognized returns 'queue', and nothing downstream can separate it from a ticket the code read and queued. Open is the defective state.

Following the value

A modified taint walk

Taint analysis marks a value at its source, follows it through a program, and reports where it reaches a sensitive sink. Security tools use it to trace untrusted input into a query, and they stop following a value once it passes a sanitizer.

Holonograph changes what the walk looks for. The sink is a decision, and the seed is an interpreted value that cannot be sanitized. Where a request came from is as important as the request itself, so provenance of a decision on interpreted data is itself interpreted, and the walk continues through it to the next decision.

Validation is not a sanitizer. A schema stops a wrong type or a malformed value, and it passes the value that is well formed and wrong. A pattern that pulls “success” out of “I hope you are a great success in life” resolves to route.SUCCESS, and every check downstream reads it as valid.

The return type is the decision’s codomain. action holds one of three exact strings and still carries the inference behind it, so the walk runs I0 → DP → I1 → DP1 and reaches the page. Moving the decision upstream moves the decision point. The next scan finds it there.

Mapping and soak

How seams are mapped and measured

In the repository

Repo scan

A scan walks the repository and produces candidate edges as structural facts: a value starts at a known source, flows through named identifiers, reaches a branch, threshold, pattern, or key, and has a default path of a given form.

An interpretation gate then adjudicates each edge as certain-interpreted, certain-mechanical, or unresolved. Only certain-interpreted edges are registered as seams. Unresolved edges stay under measurement.

The scan reports its own coverage. What the walk could not follow is listed, and partial coverage never reads as no seams.

At authorship

Builder hooks

The scan also runs as a hook inside the coding session, on every edit, at the moment of writing.

When a seam reaches an authority sink, a note lands in the session that wrote it, naming the interpretation, the decision, the sink, and anything the scan could not follow. The builder declares the seam or restructures around it.

The monitor flags seams and proposes candidate sinks and skip paths. It does not edit code. Builders →

On live traffic

Seam soak

The walk shows that a value can reach a decision. It cannot show that the decision reads the value correctly. Closing a seam makes a decision attended and monitorable, and soak measures the rest.

The lens records how often a seam’s abstention path fires, the rate of each branch, and how the decided value’s identity churns over time. An else that fires constantly shows in those rates. So does one input landing on two different branches.

Rates show behavior, and a pattern with proper abstention can still send the wrong information. Occasional judge assessments, run offline over a seam’s stored observations, score whether the value was efficacious.

Soak observations carry their own provenance, so they stay out of an agent’s default readings, and findings reach the Attention Spine.

This is how an inference moves from authority nobody granted to authority on evidence. A seam is mapped, declared with a contract, and qualifies on live evidence. It reads granted once its certainty condition is established and every dependency holds.

A model is a seam whose interpreter moves

A pattern does not rewrite itself between runs. A model can be re-routed behind an unchanged name, and the instrument scoring it is usually another model. The lifecycle is the same, with monitoring properties unique to LLM seams.

A model can sit on either side of a seam: as the interpreter whose output a rule consumes, or as the decider that takes an interpreted input and chooses an action. Holonograph labels the interpretation, the decision, and the action separately, so a model in both roles is read as two dependencies.
