Lensserver · signed binary

v0.44.32026-11-06

Asynchronous judge verdicts, with a stale-verdict alarm

  • A verdict can land as its own linked judge event. The attention queue, and event reads on request, resolve it onto its subject on production and eval runs, with several judges per subject.
  • Declare judgePendingStalenessMs on a surface and a verdict pending past that window raises a judge-pending-stale finding.
  • The finding separates verdicts dropped in transit from verdicts never emitted, so a channel drop is not read as a stopped worker.
v0.44.02026-11-05

Per-agent reads on a shared lens

  • Each agent can authenticate with its own operator token, and its events carry that verified source.
  • Analytic findings and gating partition per agent, so two agents on one surface keep separate findings and one agent's finding never gates another's.
  • A new source-conflation finding flags a pooled read hiding a per-agent split and leaves the grouping to the operator.
  • Mediated calls carry inline images and Anthropic extended-thinking traces, and the seam registry holds across instances.
v0.43.92026-11-04

Seam data per agent source

  • Seam scans from several agents coexist on one lens, each held under its own source.
  • The source is stamped at ingest from the verified operator, and seam findings, observations, soak, and analysis all read per source. A lens with one token behaves as before.
  • A forced tool choice is served on models that reject forced tool selection, and the call record shows when that path ran.
v0.43.82026-10-31

Seam-to-call attribution

  • With a seam scan on the lens, each mediated call reads back with the candidate seams on its path, graded by the evidence behind the link.
  • A seam-to-call analysis monitor shows seam reach, arm distribution, and which seams associate with failing judge dimensions.
  • Each association carries its evidence grade and makes no causal claim.
v0.43.72026-10-29

The seam-soak monitor

  • A dashboard monitor shows each seam's abstention rate, arm distribution, and judged value efficacy from its runtime observations.
  • Builder-seam and seam-soak findings stay on their own monitors, out of the default attention queue.
v0.43.62026-10-09

Vendor-native options, end to end

  • Each multiplex leg carries its stop reason and the provider's own request id, through to the light snapshot.
  • Per-vendor provider-native request options reach the model on every path, and each peer's effective options are kept with its request.
  • Call-time provenance parity: declared dimension ids read back on the call, reasoning tokens counted, and the same view in OTel and the operator console.
v0.43.32026-10-08

Errored peers are observations, not silence

  • A multiplex peer that fails is now recorded with its reason and class instead of disappearing from the comparison.
  • Instrument-floor subtraction reports honest-null where the leakage term cannot be computed, rather than cancelling the floor silently.
v0.42.32026-09-24

Vendor-native options reach the model

  • Vendor-native request options you set (for example top_k, seed, stop sequences, or vendor cache directives) now flow through every path to the model: direct calls, replay, fixture rerun, and each leg of a multiplex run.
v0.42.22026-09-20

Judge light source: attribution fix

  • The judge's requested provider and credential now resolve correctly on live traffic.
v0.42.12026-09-19

Know the judge's light source

  • Capture the judge's requested provider and credential beside the model it actually served, so a change of judge is attributed to the judge and not mistaken for a change in your own agent.
v0.42.02026-09-14

Holonograph enters beta

  • The pre-launch hardening pass is complete: security, reliability, and scoring consistency are at production grade, and Holonograph is ready for beta use.
  • Scoring produces results identical to the prior release, so upgrading changes nothing you have already measured.
v0.41.272026-09-13

Sharper refusal detection, honest health

  • Wrongful-refusal detection along a conversation was tightened to flag only clear cases, so ordinary phrasing no longer trips a false alarm.
  • Lens Health shows a measuring state instead of a false none while a slow read completes, and its vendor readout lists every model in the window, not just the latest.
v0.41.262026-09-12

A root-cause attention queue

  • Findings now carry their prerequisites: a downstream flag is marked blocked and traced to the upstream cause, so you fix the root first.
  • A finding flags when a facet is scored on the default rubric because its own reference did not resolve, so you can point it at the intended one.
  • New health findings surface when judges or scoring axes overlap, disagree, or drift together, so a real signal is easier to tell from an instrument artifact.
